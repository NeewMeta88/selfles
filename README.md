# selfles — Tilda code blocks

Этот репозиторий хранит HTML/CSS/JavaScript-код, вынесенный из сайта **selfles** на Tilda.

Репозиторий нужен как читаемая и версионируемая копия кастомного кода сайта: здесь удобнее смотреть историю изменений, ревьюить код и передавать поддержку другому разработчику, чем работать только внутри редактора Tilda.

## Как связаны Tilda и файлы в репозитории

Основная единица синхронизации — **активный блок T123 «HTML-код»** в Tilda.

**Правило синхронизации:** комментарий активного T123-блока в Tilda должен совпадать с именем соответствующего файла **без `.html`**.

Пример:

- комментарий блока в Tilda: `sticky-menu`
- файл в репозитории: `main/sticky-menu.html`

Если файл переименовывается, комментарий соответствующего T123-блока в Tilda нужно переименовать одновременно.

> Порядок блоков не кодируется номером файла. Для сопоставления используются страница Tilda, порядок активных T123-блоков и имя комментария.

### Что не считается отдельным файлом

Не каждый фрагмент HTML, видимый в редакторе, является отдельным T123-блоком.

Например, на главной странице контейнер слайдера

```html
<div class="main"><div class="slider"></div></div>
```

и контейнер точек

```html
<div class="sl-dots"></div>
```

находятся **внутри Zero Block T396** как HTML-элементы. Они являются частью разметки Zero Block и отдельно в репозитории не хранятся. Логика, которая использует эти элементы, хранится в `main/zero-block-slider.html`.

### Отключённые T123-блоки

В редакторе Tilda также остаются старые T123-блоки со статусом `off="y"`. Они не исполняются на опубликованной странице и по умолчанию **не считаются актуальной частью репозитория**.

Не нужно создавать для них файлы только ради совпадения количества блоков. Перед удалением такого legacy-блока из Tilda его следует проверить отдельно.

`styles.css` является ещё одним исключением: это не T123-блок страницы, а общий CSS из настроек сайта.

## Общий CSS — `styles.css`

Файл `styles.css` соответствует CSS из:

**Мои сайты → selfles → Настройки сайта → Добавление CSS-кода**

При изменении общих стилей необходимо синхронизировать **полное содержимое** `styles.css` с этим полем в Tilda.

Для `styles.css` нет комментария T123-блока и правило совпадения имени комментария с именем файла не применяется.

## Глобальный код в HEAD

Помимо T123-блоков и общего CSS, в Tilda есть отдельная site-wide настройка:

**Мои сайты → selfles → Настройки сайта → Вставка кода в HEAD**

На момент аудита в ней находится следующий код:

```html
<meta name="yandex-verification" content="c75d10a8a351718c" />
<meta name="twitter:card" content="summary_large_image" />
<meta name="twitter:image" content="https://static.tildacdn.com/tild3432-3335-4535-b164-346661383263/selfles_cover.png" />
<meta name="p:domain_verify" content="4621a2b3393da01b440c81a2ce3f349e"/>
```

Это глобальная настройка проекта Tilda, а не HTML-блок отдельной страницы. Поэтому для неё нет комментария T123 и отдельного файла в текущей структуре репозитория.

При передаче сайта или изменении SEO/social/verification-настроек этот блок нужно проверять отдельно: он содержит verification-теги Яндекса и Pinterest, а также Twitter/X card metadata и ссылку на изображение превью.

### Внешняя зависимость `preset-product-mapping`

`main/preset-product-mapping.html` не содержит всю реализацию локально: он подключает CSS и JavaScript с `disk.nocodered.ru`.

Это внешняя зависимость проекта, а содержимое этих файлов не версионируется в этом репозитории. Если новому разработчику потребуется менять или восстанавливать эти внешние файлы, доступ и актуальный source-of-truth нужно запросить у менеджера проекта.

Не следует считать `disk.nocodered.ru` Google Drive или другим конкретным сервисом без отдельной проверки: в текущем коде это просто внешний HTTP-host, с которого загружаются два runtime-файла.

### Важный порядок конструктора

`set-constructor-part-1.html` должен находиться **выше** `set-constructor-part-2.html`: вторая часть использует данные, опубликованные первой через `window.SELFLES_CONSTRUCTOR_SHARED`.

## Как вносить изменения

Для T123-блоков:

1. Определить страницу Tilda по папке репозитория и, при необходимости, page id.
2. На странице найти активный T123-блок по комментарию.
3. Найти одноимённый `.html`-файл в соответствующей папке репозитория.
4. Внести изменение в одной версии кода и полностью синхронизировать вторую.
5. Если меняется имя файла — одновременно изменить комментарий T123-блока.
6. Сохранять порядок зависимых блоков, особенно `set-constructor-part-1` → `set-constructor-part-2`.
7. Опубликовать изменённую страницу Tilda и проверить результат на опубликованном сайте.

Для общего CSS:

1. Открыть **Мои сайты → selfles → Настройки сайта → Добавление CSS-кода**.
2. Синхронизировать содержимое поля с `styles.css`.
3. Сохранить настройки и переопубликовать необходимые страницы сайта.

Для глобального HEAD-кода:

1. Открыть **Мои сайты → selfles → Настройки сайта → Вставка кода в HEAD**.
2. Сверить verification/meta-теги с разделом **«Глобальный код в HEAD»** этого README.
3. После изменения сохранить настройки и переопубликовать необходимые страницы сайта.

Рекомендуется делать изменения через отдельную git-ветку и Pull Request, особенно если код меняет корзину, каталог, наличие товаров или товарные страницы.
