# selfles — Tilda code blocks

Этот репозиторий хранит HTML/CSS/JavaScript-код, вынесенный из сайта **selfles** на Tilda.

Репозиторий нужен как читаемая и версионируемая копия кастомного кода сайта: здесь удобнее смотреть историю изменений, ревьюить код и передавать поддержку другому разработчику, чем работать только внутри редактора Tilda.

## Как связаны Tilda и файлы в репозитории

Большинство `.html`-файлов соответствуют отдельным HTML-кодовым блокам на определённых страницах Tilda.

**Правило синхронизации HTML-блоков:** название комментария/подписи у кодового блока в Tilda должно совпадать с именем файла **без `.html`**.

Пример:

- комментарий блока в Tilda: `sticky-menu`
- файл в репозитории: `main/sticky-menu.html`

Если файл переименовывается, комментарий соответствующего кодового блока в Tilda нужно переименовать одновременно.

> Порядок блоков в Tilda не кодируется номером файла. Источник истины для сопоставления — имя блока и имя файла.

`styles.css` является исключением: он не соответствует HTML-блоку страницы и хранится в общих настройках сайта Tilda. Для него правило совпадения имени комментария с именем файла не применяется.

## Общий CSS — `styles.css`

Файл `styles.css` соответствует CSS, который находится в настройках всего сайта Tilda:

**Мои сайты → selfles → Настройки сайта → Добавление CSS-кода**

При изменении общих стилей необходимо синхронизировать **полное содержимое** `styles.css` с этим полем в Tilda.

В отличие от `.html`-файлов:

- `styles.css` не относится к отдельной странице;
- для него нет отдельного HTML-кодового блока;
- для него нет комментария блока, который нужно синхронизировать с именем файла.

## Как вносить изменения

Для HTML-блоков:

1. Определить страницу Tilda по папке репозитория.
2. На этой странице найти HTML-кодовый блок по комментарию/названию.
3. Найти одноимённый `.html`-файл в соответствующей папке репозитория.
4. Внести изменение в одной версии кода и полностью синхронизировать вторую.
5. Если меняется имя файла — одновременно изменить комментарий блока в Tilda.
6. Для split-блоков (`set-constructor-part-1` / `set-constructor-part-2`) сохранять порядок подключения.
7. Опубликовать изменённую страницу Tilda и проверить результат на опубликованном сайте.

Для общего CSS:

1. Открыть **Мои сайты → selfles → Настройки сайта → Добавление CSS-кода**.
2. Синхронизировать содержимое поля с `styles.css`.
3. Сохранить настройки и переопубликовать необходимые страницы сайта.

Рекомендуется делать изменения через отдельную git-ветку и Pull Request, особенно если код меняет корзину, каталог, наличие товаров или товарные страницы.

## Перед переводом репозитория в public

Перед открытием репозитория рекомендуется:

- привести комментарии всех HTML-кодовых блоков в Tilda к именам файлов из этого README;
- проверить в Tilda, какой из блоков `home-catalog-pager` / `main-catalog-rows` реально используется, и после подтверждения удалить legacy-версию, если она действительно больше не нужна;
- сверить `styles.css` с текущим содержимым **Настройки сайта → Добавление CSS-кода**;
- проверить внешние зависимости и ссылки на сторонние хостинги, особенно старые подключения `disk.nocodered.ru`;
- убедиться, что статические fallback-данные товаров не воспринимаются как актуальный источник наличия;
- повторно проверить текущие файлы и историю репозитория на секреты перед публикацией;
- выбрать и добавить `LICENSE`, если код предполагается разрешать использовать третьим лицам. Публичный репозиторий сам по себе не задаёт лицензию на использование кода.
